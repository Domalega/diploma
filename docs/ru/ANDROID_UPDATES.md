# Обновление Jotstride на Android

[English](../ANDROID_UPDATES.md) · Русский

Если у вас версия 0.3.0 или новее, установите обновление поверх текущей версии. База, неотправленные изменения и настройки останутся на телефоне. Если у вас версия 0.2.0, сначала [сохраните данные](#переход-с-версии-020).

## Как установить обновление

1. В Jotstride откройте **Настройки → Обновления приложения → Проверить обновления**. Если в приложении уже есть баннер об обновлении, можно начать с него.
2. Нажмите **Скачать и обновить**. Загрузка начинается только по вашему запросу. Android WorkManager может повторить неудачную загрузку до трёх раз.
3. Если Android попросит разрешить установку APK из Jotstride, включите это разрешение в настройках системы. Затем подтвердите установку. При отмене текущая версия и данные останутся на телефоне.

Перед запуском установщика Jotstride проверяет размер файла, контрольную сумму SHA-256, имя пакета, версию и сертификат подписи APK.

При запуске Jotstride проверяет обновления, если с последней успешной проверки прошло больше шести часов. Кроме того, приложение планирует фоновую проверку примерно раз в сутки. Android может отложить проверку. О доступности каждой новой версии приходит одно уведомление. Когда файл скачан, приходит отдельное уведомление о готовности к установке. При отключённых уведомлениях обновления видны в приложении. После принудительной остановки снова откройте Jotstride, чтобы возобновить автоматические проверки.

## Переход с версии 0.2.0

Предварительная версия 0.2.0 подписана старым ключом. Для перехода на постоянный ключ Android требует один раз переустановить приложение. **Оставьте 0.2.0 на телефоне, пока не проверите результат обмена или резервную копию.**

### Вариант 1. Синхронизируйте данные с сервером

1. Откройте 0.2.0 с доступом в интернет и нажмите **Обменяться сейчас**. Дождитесь успешного обмена и убедитесь, что неотправленных изменений больше нет.
2. Откройте веб-версию и проверьте, что последние записи на месте. Повторите для каждого аккаунта, которым пользовались на телефоне.
3. Удалите 0.2.0, установите актуальный APK и войдите снова.

### Вариант 2. Экспортируйте резервную копию

Воспользуйтесь этим вариантом, если синхронизация недоступна или нужна отдельная копия данных.

1. Установите на компьютер Python 3 и [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools). Подключите телефон по USB, включите отладку по USB и разрешите подключение компьютера. Команда `adb devices` должна показать ровно один доступный телефон.
2. Скачайте `android-export-legacy.py` из релиза и выполните команду ниже. Если `adb` отсутствует в PATH, добавьте `--adb "C:\path\to\adb.exe"`. Скрипт останавливает приложение и создаёт новый файл резервной копии. Он оставляет приложение и его данные на телефоне и отказывается перезаписывать существующую копию.

   ```sh
   python android-export-legacy.py daymark-0.2-backup.json
   ```

3. Дождитесь сообщения `Saved and verified`. Скопируйте JSON на телефон, например в папку «Загрузки». В файле есть личные записи, поэтому храните его в закрытом месте.
4. Удалите 0.2.0 и установите актуальный APK.
5. На экране входа **до первого входа в аккаунт** нажмите **Восстановить копию из 0.2** и выберите JSON-файл. Дождитесь сообщения об успешном восстановлении.
6. Войдите в тот же аккаунт и проверьте записи и неотправленные изменения. Если аккаунтов несколько, войдите в каждый по очереди. При конфликте с данными на сервере выберите версию, которую хотите оставить.

Копия содержит данные календаря, списка дел, Канбана и учёта лекарств, очередь отправки и сведения о конфликтах. Пароли и токены входа в копию не входят. Заново выберите язык и оформление и настройте разрешения Android. Отладку по USB после переноса можно выключить. Последующие обновления подписываются тем же ключом и устанавливаются поверх приложения.

Приложение проверяет файл и восстанавливает документы всех аккаунтов одной транзакцией. Восстановление доступно только до первого входа, пока хранилище пустое. APK загружается с GitHub независимо от API календаря. Для обмена самими записями нужен доступный `/api/sync`.

## Как собрать и опубликовать новую версию

1. Увеличьте `versionCode` и обновите `versionName` в [`apps/android/version.properties`](../../apps/android/version.properties). Сохраните идентификатор приложения и ключ подписи.
2. Соберите подписанный APK без отладочного режима с помощью [процесса Native apps](../../.github/workflows/native-apps.yml). Процесс использует секреты репозитория `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD`. Храните защищённую копию ключа отдельно от артефактов и кешей. При потере ключа обновить уже установленные приложения не получится.
3. Перед упаковкой обновите [`apps/android/release-notes.txt`](../../apps/android/release-notes.txt) или задайте `DAYMARK_UPDATE_NOTES`. [Скрипт упаковки](../../scripts/package-android-update.cjs) создаёт файлы релиза на основе метаданных, полученных из APK через `aapt`.
4. Выполните модульные тесты и тесты на эмуляторе для расписания, синхронизации, обновлений и сохранности данных. Проверьте доставку в фоне и влияние ограничений батареи на телефоне.
5. Создайте черновик релиза с тегом `native-preview-X.Y.Z`. Проверьте наличие `Daymark-Android-X.Y.Z.apk`, `android-update.json` и `SHA256SUMS.txt`, затем опубликуйте релиз. Оставьте скрипт экспорта доступным для пользователей 0.2.0. Если нужно изменить APK или манифест, опубликуйте новую версию.

Приложение читает список опубликованных релизов, потому что GitHub исключает предварительные выпуски из ответа `releases/latest`.

# Сквозное шифрование

[English](../ENCRYPTION.md) · Русский

По умолчанию сквозное шифрование выключено. Оно защищает текущие данные: заметки, даты и время, список дел, колонки, задачи и историю Канбана, расписание лекарств и отметки о приёме. Прежние записи на сервере остаются в незашифрованном виде и со временем могут устареть.

**После включения шифрования сохраните доступ хотя бы на одном подключённом устройстве.** Если потерять все ключи устройств, которые Jotstride создал для аккаунта, сброс пароля не вернёт зашифрованные данные. В этой версии нельзя восстановить, отозвать или заменить ключ потерянного устройства.

Чтобы включить шифрование, подключитесь к интернету и откройте **Настройки → Сквозное шифрование → Включить шифрование**. Jotstride создаст ключи автоматически. Пароль аккаунта менять не нужно.

## Как подключить другое устройство

1. Подключите оба устройства к интернету, обновите Jotstride и войдите на обоих в один и тот же аккаунт.
2. На новом устройстве нажмите **Скопировать ссылку подключения** и отправьте ссылку на устройство, у которого уже есть доступ.
3. Откройте ссылку на подключённом устройстве. Убедитесь, что она пришла с вашего нового устройства, и нажмите **Подтвердить подключение**.
4. Оставьте календарь открытым на новом устройстве. Приложение периодически проверяет, подтверждён ли запрос. Когда устройство получит зашифрованную копию ключа, календарь откроется автоматически. Для немедленной проверки нажмите **Повторить**.

Если ссылка открылась в другом браузере, перейдите в уже подключённое приложение. Откройте **Настройки → Сквозное шифрование → Подключить другое устройство**, вставьте ссылку и нажмите **Проверить подключение**. Убедитесь, что запрос пришёл с вашего нового устройства, и нажмите **Подтвердить подключение**.

### Доступ из предыдущей версии

Если вы пользовались прежним шифрованием с секретной фразой, устройство с сохранённым доступом может подключить новое по той же инструкции. Если ключ нигде не сохранён, на новом устройстве откройте **Доступ из предыдущей версии** и один раз введите старую фразу. Jotstride проверит её и сохранит доступ для этого устройства. Формат зашифрованного документа при этом сохранится.

## Как выключить шифрование

На подключённом устройстве с доступом в интернет откройте **Настройки → Сквозное шифрование → Выключить шифрование** и подтвердите действие. Jotstride сначала синхронизирует данные и предложит разрешить конфликты, если они есть. Сервер проверит версию зашифрованного документа и восстановит обычные записи одной транзакцией. Если версия уже изменилась или проверка не прошла, шифрование останется включённым.

Сервер сохраняет в архиве аккаунта последний зашифрованный документ и предыдущий снимок обычных данных. На устройстве остаются зашифрованная копия и ключи. Jotstride сохраняет существующую историю действий и добавляет недостающие события. Другие подключённые устройства объединяют неотправленные изменения с обычными записями или предлагают разрешить конфликт. При повторном включении шифрования Jotstride создаёт новый ключ данных и заново регистрирует устройство. Если остались неотправленные изменения из предыдущего периода шифрования, приложение сохранит их и сообщит о них.

Перед выключением шифрования на Android обновите приложение до версии 0.4.2 или новее. Эти версии умеют восстанавливать локальный снимок и возобновлять обычную фоновую синхронизацию. После выключения сквозного шифрования Android Keystore и Windows DPAPI продолжают защищать данные, которые им передаёт приложение.

## Как работают ключи устройств

- **Создание ключей.** Первое устройство создаёт случайный 256-битный ключ данных и пару ключей ECDH P-256. Каждое подключённое устройство получает зашифрованную для него копию ключа данных. Для этого используются временный ключ ECDH, HKDF-SHA-256 и AES-256-GCM. Сервер получает открытые ключи устройств и зашифрованные копии. Закрытые ключи и ключ данных в открытом виде остаются у клиентов.
- **Защита данных.** Jotstride использует AES-GCM с новым 12-байтным одноразовым значением и 128-битным тегом аутентификации для каждого зашифрованного пакета. Аутентифицируемые данные связывают пакет с адресом API, аккаунтом и типом операции, будь то локальное хранение или обмен с сервером. При передаче ключа дополнительно проверяются устройство-получатель и его открытый ключ. [Спецификация Web Crypto API](https://www.w3.org/TR/webcrypto-1/)
- **Подтверждение устройства.** Ссылка содержит только открытые данные подключения. Перед шифрованием ключа подтверждающее устройство сравнивает полный открытый ключ из ссылки с ключом из запроса на сервере. Это позволяет обнаружить подмену ключа получателя. Решение о подключении принимает пользователь. Запрос действителен 30 минут без продления. После подтверждения API отклоняет попытки заменить выданную зашифрованную копию ключа.
- **Хранение ключей.** Браузер хранит закрытый ключ в IndexedDB как ключ Web Crypto, который нельзя экспортировать. Защита файлов профиля зависит от браузера и операционной системы. На Android закрытый ключ защищён Keystore, а на Windows — DPAPI текущего пользователя с отдельной дополнительной энтропией для этой операции. Нативные клиенты хранят в IndexedDB защищённую копию и при открытии импортируют ключ с запретом экспорта.
- **Выход из аккаунта.** Зашифрованная копия ключа данных остаётся на устройстве для повторного входа, в том числе без интернета. Выход удаляет активный ключ из состояния приложения и отменяет напоминания. При следующем входе подключённое устройство откроет данные автоматически. Jotstride очищает временные буферы открытых ключевых данных после использования, насколько это позволяет среда JavaScript.

## Хранение и синхронизация

Сервер по-прежнему видит электронную почту, сведения о входе и сбросе пароля, открытые ключи, тип устройства, размеры записей и время запросов. Токены аккаунта и настройки оформления находятся вне зашифрованного документа.

Jotstride хранит текущий документ и последнее состояние с сервера в зашифрованном виде, отдельно для каждого аккаунта и адреса API. Ключ устройства сохраняется до первой отправки документа. Старый кеш ответов очищается после успешной записи в локальное зашифрованное хранилище. Web Locks не дают нескольким вкладкам записывать данные одновременно. Если сохранить изменение на устройстве не удалось, приложение отклоняет его. Если сеть пропала после сохранения, приложение может отправить изменение позже.

Запись через `/api/vault` использует ту же блокировку на уровне аккаунта, что и обычная запись календаря. Проверка версии отклоняет устаревшие отправки. Клиент расшифровывает документы на устройстве, объединяет независимые изменения и предлагает выбрать версию при конфликте, в том числе если расходятся расписания или лимиты задач в работе на доске. При активном зашифрованном хранилище обычные методы API календаря для аккаунта недоступны. Аккаунты с выключенным шифрованием продолжают обмениваться данными через обычные методы API.

Пока интерфейс открыт, Jotstride запускает обмен после правок, при возвращении в приложение, при восстановлении сети и по таймеру. Принудительный обмен доступен по кнопке **Обменяться сейчас** в настройках. Обычная фоновая синхронизация Android для зашифрованных аккаунтов отключена. Напоминания продолжают срабатывать при закрытом приложении. Изменения с других устройств попадут в расписание при следующем обмене с открытым интерфейсом. Операционная система может показывать текст напоминаний в уведомлениях.

## Развёртывание и проверка

До обновления клиентов разверните сервер с новой таблицей `vaultDevices` и API для устройств. Android 0.4.1 и обновлённое приложение Windows добавляют системную защиту закрытого ключа. Перед включением шифрования обновите старые нативные клиенты. Для работы нужны HTTPS, Web Crypto, IndexedDB и Web Locks. Используйте постоянный адрес API, поскольку он входит в контекст шифрования.

Размер сериализованного документа до шифрования, включая историю действий, ограничен 1,8 млн кодовых единиц JavaScript. У браузерного хранилища есть собственная квота. Если документ превышает лимит, приложение отклоняет его целиком без удаления отдельных записей. Шифрование не очищает старые страницы SQLite, выгрузки и резервные копии. При компрометации клиента, вредоносном обновлении интерфейса, XSS или доступе к разблокированному профилю ключи и данные могут стать доступны постороннему. Новое устройство не может само определить, что первый загруженный документ заменили более старой версией.

В тестах проверяются подтверждение устройства, подмена открытого ключа, истечение запросов, запрет замены выданного ключа, офлайн-доступ, сохранение доступа после перезагрузки и выхода, потеря ответа на отправку, доступ из прежней версии, конфликты и изоляция аккаунтов. Нативные тесты проверяют защиту Keystore и DPAPI и сохранность данных. Перед выпуском подключите два профиля браузера или два устройства и проверьте обновление поверх установленного приложения.
